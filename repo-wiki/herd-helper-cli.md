# Herd Helper CLI (`tk herd`, `internal/herd/*`)

Layer 2 of the herdr agent-agnostic orchestrator (design: `docs/design/herdr-orchestrator.md`; conventions: `skills/ticks/references/herdr-runner.md`, which after epic `gyz` presents the helper as the primary mechanism). Built by epic `gyz` on branch `epic/gyz`, stacked on `epic/ias` (PR #37).

## Package map

- `internal/herd/client` — typed unix-socket JSON client, protocol 19 pinned fail-closed. The socket serves one request per connection; only `events.subscribe` streams. Dual event-envelope spellings handled (session-wide/`events.wait` = underscored; the three pane-scoped subscriptions = dotted, no `data.type`); a live drift-guard test fails loudly if herdr changes this. Current-status replay on subscribe is **conditional on a matching `agent_status` filter**. Client validates subscription scoping before dialing (herdr silently ignores unknown fields). `CallTimeout` is a hard ceiling (min with caller deadline).
- `internal/herd/config` — strict `.tick/runners.toml` loader (BurntSushi/toml for complete unknown-key reporting + present-vs-omitted), tier resolution (`roles.R.tiers.T` → `roles.R` → `roles.implement`, args replace never merge), per-kind model/effort→argv compilation with typed `RefusalError` (fail-closed on impossible kind×model cells), six-cell substrate `Decide` with injectable prober.
- `internal/herd/state` — atomic run-state manifests under `.tick/logs/herd/<epic>/<tick>.json` (gitignored local run state; the one path under `.tick/` the helper may write).
- `internal/herd/spawn` — worktree.create → agent.start → **first-round-trip content gate** (echo-anchored classification: silent-drop→re-send once / error-content→fail with excerpt / answered) → real prompt (non-blocking dispatch by default; `tk herd wait` is the fan-in) → manifest + `runner-state:` note line. Session ids captured post-gate.
- `internal/herd/wait` — event-driven fan-in: three filtered subscriptions per worker (idle/done/blocked) so the conditional-replay contract closes the list→subscribe race by construction; reconcile-then-resubscribe once on stream death; no polling.
- `internal/herd/collect` — four artifact-presence verdicts (ready-to-merge / no-commits / missing-result / boundary-violation), parsed worker `STATUS` reported independently (BLOCKED-with-commits is mergeable + escalate line). Never merges.
- `internal/herd/cleanup` — preview-is-the-plan; workspace remove → `branch -d` (never -D) → manifest last; refuses `blocked|working` workers and unmerged branches (liveness deliberately narrowed: interactive CLIs never exit, so "live" alone is not "incomplete"). Restores pre-call focus after `--apply` (removing/closing a workspace moves focus to a neighbour and herdr has no flag to prevent it).
- `internal/herd/reconcile` — five-class crash plan (live-worker / dead-resumable / dead-with-work / stale-no-work / unknown); contradictions outrank (incl. uncountable-branch → unknown, never stale); exact per-kind resume argv under fresh `-r<N>` names; read-only except `--adopt`.

## Live-verified operational facts (epic gyz smoke, herdr 0.8.0)

- Fresh worktree pane isn't a usable shell for ~0.3 s (`agent_pane_busy`) — spawn retries bounded.
- `agent.start` returns `launch_pending`; wait for `interactive_ready`, not status (~3 s).
- `agent_prompt_stalled` is a non-signal: it fires even when the worker answered <1 s. Settle, read the pane, let the gate classify.
- Fire-and-forget dispatch races the fan-in — spawn confirms dispatch by waiting bounded for `working` (non-fatal `DispatchUnconfirmed` warning).
- `worktree.create` against a repo with no open workspace opens TWO workspaces (worktree + implicit source checkout; the response names only one) — cleanup must cover the source workspace.
- **Harness background tasks are invisible to herdr lifecycle** (uvv wave 2): a claude worker parked its test gate in background shells and ended its turn → herdr `done`, wait settled, collect refused (no commits/RESULT — the durable layer caught it). Worker template now forbids backgrounding the final gate; recovery = continue the same worker (`agent prompt` + `--until working` dispatch-confirm), never redispatch. Also explains "worker looks done but orch still waiting" reports.
- Focus: `--no-focus` works on create; workspace remove/close ALWAYS moves focus and never returns it — hence cleanup's focus restore.
- **Explicit targets always**: herdr commands that default to the UI-focused workspace/pane when no target is given (`plugin pane open`, `pane split`, …) must ALWAYS carry an explicit target pinned to run-created resources. The user jumps between sessions — focus is never a safe implicit target (field-observed: a verification pane opened in the user's unrelated focused workspace).

## Epic zz0 additions (complete — awaiting project checkpoint)

Rule: new fake capability goes in herdtest, never in a package-local fake — package-local fake drift caused the gyz review blocker. herdtest cannot import `client` (cycle with client's in-package tests), so consumer packages adapt via type aliases/seam files.
- Cleanup `--apply` re-checks worker liveness per plan immediately before its destructive step; an unanswerable re-check refuses (`recheck-failed`) — silence is not proof it's safe to kill an agent.
- `plugins/herdr-ticks/` — mission-control plugin (dev: `herdr plugin link`; keep the link pointed at the MAIN checkout, not an agent worktree). Plugin schema gotchas (live-verified 0.8.0): `contexts`/`placement` are closed enums that fail the link; **`events.on` is NOT validated — typos link cleanly and never fire; prove hooks via `herdr plugin log list`**; command is argv-only, cwd = plugin root, target repo from `HERDR_PLUGIN_CONTEXT_JSON`; manifest edits need unlink+link; `action invoke` returns `running` immediately — only the plugin log verifies.

## First production run (epic uvv, 2026-08-12) — dogfood findings

The tk-skills epic ran on the herd substrate itself (runners.toml substrate=herdr, claude workers via tiers). Findings, all fixed in-flight: (1) wait's deadline guards race the deadline-induced dial error — fixed twice, final form compares wall-clock against ctx.Deadline() (race-free by construction); (2) the harness-background-tasks settle gap (see Live-verified facts above) — a worker parked its gate in claude background shells, collect caught it, worker template hardened; (3) continuation recipe proven: prompt the same worker + `--until working` dispatch-confirm + re-collect. Also: waited_ms=16 on an already-settled worker proved the filtered-replay fast path; cleanup's focus restore fires routinely. Design decision (human): `tk skills install` is detection-first — installs into every convention dir (`.claude/skills`, `.agents/skills` — PLURAL, live-verified) present at the repo root, ~99% harness coverage without a location registry. Further template refinements from the run: workers must not commit their RESULT file (8ct did — `git add -A` grabs it if written pre-commit; template now orders it post-commit), and a mid-flight spec correction reached a working worker via a queued `agent prompt` (picked up in-turn, applied cleanly — continuation works for corrections, not just failures).

## Mop-up epic findings (fit, 2026-08-12)

- **Codex startup gates**: fresh codex spawns can stall pre-composer on (a) workspace trust and (b) SessionStart-hooks review (fires when a user-level hook file changes, e.g. the herdr integration updating). Both are one-time machine-level approvals; herdr classifies neither as `blocked`. After approving once, spawns are clean.
- **Codex workspace-write cannot commit in linked worktrees** — git metadata lives under the main repo's `.git/worktrees/`, outside the sandbox. Worker correctly reported NEEDS_CONTEXT; orchestrator completed the commit. **Fixed (tick ipo): `--add-dir <git-common-dir>`, not danger-full-access.** The kind row in `internal/herd/config/kinds.go` declares a *computed per-spawn extra*; `Compile` renders it from a `config.SpawnContext` and refuses the spawn when the dir is unresolvable (compiling the sandbox without the grant = a worker that starts green and cannot commit). The path comes from `spawn.GitCommonDir` (`git rev-parse --git-common-dir`, never a hardcoded `.git`). Argv order is now full-auto template → computed extras → model/effort → args. The danger-full-access route was rejected on herdr-kinds.md's own argument: it removes the sandbox, which is only appropriate inside an already-sandboxed environment. **Still open:** the harness-substrate path in `skills/ticks/references/codex-runner.md` (~line 37) has the same defect — `git worktree add` + `codex exec --sandbox workspace-write` with no `--add-dir`.
- **RESULT-file/cleanup collision**: the no-commit-RESULT rule makes every worktree dirty at cleanup, and the no-force guard (correctly) refuses. Fix (tick esq): cleanup consumes exactly the tick's own RESULT file (archiving beside the manifest) and still refuses any other dirt.
- Cross-vendor wave proven in production: one event-driven wait over claude+codex workers; both settled within 8s of each other.

## Experiments (bucket nmn, 2026-08-12 — reports in docs/design/experiments/)

- **Layout restore** (`layout.export`/`apply`, socket-only): proven incl. the killer feature — pane nodes carry `command`/`env`, so an applied layout relaunches processes (dashboard restore in one call). Quirks: apply rebuilds as a NEW tab id; focus-scoped export ambiguity. Worth a real `tk herd layout save/restore` tick.
- **pane.graphics**: works behind `experimental.kitty_graphics` (png/rgb/rgba + grid placement); needs an attached kitty-capable terminal for cell metrics/rendering. Optional-only enhancement; not tick-worthy yet.
- **Remote fleets**: `--remote` attaches a client to a remote server — so orchestrator-on-remote works TODAY (run the epic there, attach to watch); local-orchestrator-over-remote-socket needs a remote-aware durable layer (documented gap). Probes ran in an isolated `herdr --session tkexp server` with a scratch HERDR_CONFIG_PATH — main session/config never touched.

## Conventions

Exit codes: `GetExitCode` is now purely typed (`errors.As` on `ExitError`; substring heuristics removed in epic zz0 — usage errors are converted at the source via `SetFlagErrorFunc` + a tree-wide `usageArgs` wrapper, so new commands are correct by construction). Two observable changes recorded in CHANGELOG: EINVAL-shaped runtime errors 2→1; `NoArgs` arity mistakes 1→2. The residual inconsistency noted here after gyz (~25 commands wrapping repoRoot/tick-not-found failures as exit 1) was closed in epic fit (tick jg5): `repoRoot()` itself returns `ExitError{ExitNoRepo}` and every tick lookup goes through `notFoundIfMissing` (`cmd/tk/cmd/lookup.go`), so no-repo is 3 and missing-tick is 4 everywhere, pinned by the table in `cmd/tk/cmd/exit_normalization_test.go`. Only `os.IsNotExist` is 4 — a corrupt tick file stays 1, same rule as the herd manifests. The wait TestWaitTimeout contention flake is documented as environmental in `.tick/config.md` Testing. Smoke: `bash scripts/verify-herd-helper.sh [--quick]` (also a Closeout Evidence Command in `.tick/config.md`); full mode includes the kill-9 reconcile drill. Field report: `docs/design/herd-helper-smoke-report.md`.
